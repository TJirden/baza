# Системные правила поведения ИИ-разработчика (Antigravity) в проекте Baza

Этот файл является руководящим документом для ИИ-ассистентов, работающих с проектом **Baza**. Соблюдение этих правил обязательно для сохранения целостности архитектуры, качества кода и стабильности системы.

---

## 1. Технологический стек и инфраструктура

При написании или изменении кода строго придерживайся следующего стека:
- **Язык программирования:** Java 25 (используй современные конструкции языка, такие как `record`, Pattern Matching для `switch`/`instanceof`, текстовые блоки).
- **Фреймворк:** Spring Boot 4.0.x (Spring Data JPA, WebMVC).
- **ИИ-интеграция:** Spring AI (версии 2.x) с использованием мультимодальных моделей Google Gemini (`gemini-3.5-flash` для чата и модерации, `gemini-embedding-001` для векторных представлений).
- **База данных:** PostgreSQL с расширением `pgvector` (интегрировано через `VectorStore` из Spring AI).
- **Библиотека Telegram Bot:** `java-telegram-bot-api` (Pengrad) версии 9.6.0.
- **Кэширование:** Caffeine Cache (используется для кэширования тяжелых мультимодальных ответов модели с использованием Soft References).
- **Сборка проекта:** Gradle (Kotlin DSL, `build.gradle.kts`).
- **Стиль и форматирование кода:** Spotless с `palantirJavaFormat("2.90.0")`.

---

## 2. Архитектурные паттерны проекта

Соблюдай устоявшиеся архитектурные паттерны:
1. **Command Pattern для Telegram-бота:**
   - Каждая команда бота должна наследоваться от интерфейса `cringe.baza.bot.command.Command`.
   - Регистрация и роутинг команд происходят автоматически через `CommandRouter` и `BotUpdateListener`. Никогда не прописывай логику разбора команд вручную в слушателях обновлений.
2. **State Machine для интерактивного взаимодействия:**
   - Если пользователь находится в процессе выполнения сценария (например, режим Tinder-оценки мемов `/swipe` или пошаговое сохранение `/save`), его состояние отслеживается через `UserSessionService` (`UserState`).
   - Обработка сообщений в определенном состоянии выносится в отдельные специализированные классы-обработчики (например, `SwipingStateHandler`, `AwaitingSaveStateHandler`).
3. **Разделение векторного и реляционного хранилищ:**
   - `MemeVectorRepository` реализует интерфейс `IdRepository` и является единой точкой доступа для синхронизации векторной базы данных (`VectorStore` от Spring AI) и реляционной БД (`MemeModerationRepository`).
   - Метаданные и ELO-рейтинги хранятся в JPA-сущностях (пакет `cringe.baza.domain`), в то время как неизменяемые DTO и модели обмена данными описываются в виде `record` (пакет `cringe.baza.model`).
4. **Асинхронный пайплайн обработки мемов:**
   - Тяжелые операции анализа изображений, OCR, цензуры и дедупликации вынесены в `AsyncMemeService` и выполняются асинхронно с помощью пула потоков `memeAsyncExecutor` (настроен в `AsyncConfig`).
   - Статус обработки шагов транслируется пользователю в Telegram в реальном времени редактированием служебных сообщений.

## 3. Правила написания кода (Clean Code)

- **Форматирование:** Весь измененный код Java должен быть отформатирован через Spotless. Всегда проверяй форматирование с помощью команды `./gradlew spotlessApply`.
- **Иммутабельность:** Предпочитай `record` для передачи данных, DTO, результатов анализа и структур, не требующих изменения состояния.
- **Lombok:** Используй аннотации Lombok (`@Getter`, `@Setter`, `@NoArgsConstructor`, `@RequiredArgsConstructor`, `@Slf4j`) для JPA-сущностей и сервисов. Избегай написания бойлерплейт-методов вручную.
- **Инъекция зависимостей:** Используй инъекцию зависимостей через конструктор (предпочтительно с помощью `@RequiredArgsConstructor` от Lombok). Никогда не используй `@Autowired` на полях.
- **Логирование:** Всегда логируй ключевые этапы бизнес-логики (особенно ИИ-анализ, кэширование и ошибки сетевых запросов) с помощью `@Slf4j` на уровне `info`, `warn` или `error`.

## 4. Критические ТАБУ (Чего делать НЕЛЬЗЯ)

1. **НЕ дублируй вызовы ИИ для одного и того же файла:**
   - Для анализа изображения, извлечения текста (OCR) и проверки цензуры используй исключительно кэширующий сервис `AiMemeAnalysisService`. Он делает ровно один сетевой запрос к Gemini API, разбирает комбинированный ответ и кэширует его в Caffeine. Вызов разрозненных сервисов напрямую без крайней необходимости запрещен.
2. **НЕ изменяй логику поиска без сохранения гибридности (RRF):**
   - Поиск в `MemeVectorRepository` реализован по принципу **Reciprocal Rank Fusion (RRF)**. Он совмещает семантический поиск (векторный) и полнотекстовый поиск (по OCR-тексту и описанию мема через `ILIKE`). Любые изменения в поиске должны сохранять оба канала ранжирования и объединять их с весами RRF.
3. **НЕ игнорируй контроль видимости (Visibility Control):**
   - Все мемы имеют уровни видимости: `PUBLIC`, `PRIVATE`, `GROUP`. При поиске, баттлах, дуэлях и генерации дайджестов всегда проверяй права доступа пользователя к мему (принадлежность к группе, владение мемом).
4. **НЕ делай синхронных сетевых вызовов в основном потоке бота:**
   - Любые взаимодействия с внешними API, включая скачивание медиафайлов из Telegram и запросы к Google Gemini, должны происходить либо в асинхронных методах (`@Async`), либо в фоновых потоках, чтобы не блокировать обработку обновлений бота.
5. **НЕ ломай ELO-алгоритм баттлов:**
   - Рейтинг мемов рассчитывается строго по формуле ELO с K-фактором = 32. Любые изменения в системе оценки должны тестироваться на сохранение математической корректности баланса рейтинга.
6. **НЕ отключай валидацию Gradle-сборки:**
   - Перед завершением любой задачи обязательно убедись, что проект собирается без ошибок с помощью `./gradlew compileJava` и тесты проходят успешно (`./gradlew test`).
